# Stage 4: Dialect Hygiene, Complete Omission, and Strawman Bans

Large language models train across heterogeneous code repositories containing multiple programming languages, database dialects, and cloud configurations. When generating code for a specific platform, models exhibit dialect contamination: blending syntax tokens from competing systems into the target language.

```sql
-- Target dialect: GoogleSQL (No foreign materialization hints)
WITH filtered_events AS (
  SELECT event_id, user_id, event_ts
    FROM `telem_traffic_01_lnd.event_fact`
   WHERE event_ts >= TIMESTAMP('2026-03-01 00:00:00 UTC')
)
SELECT user_id, COUNT(event_id) AS event_qty
  FROM filtered_events
 GROUP BY user_id
```

## 1. The Dialect Bleed Failure Mode

During the development of the BigQuery skill, early iterations repeatedly hallucinated constructs from alternative SQL engines. In thread `e1bbc0bd-542e-427d-9b86-64c3413b2ce4`, the agent generated queries containing `WITH ... AS MATERIALIZED`, a construct supported in PostgreSQL and Snowflake but invalid in GoogleSQL. 

The user intervened:

> *"I dont think ' AS MATERIALIZED (' is allowed in bigquery. also SELECT AS VALUe is not, please check, if not, just remove them from skill"*

When an agent consults a skill contaminated with foreign dialect constructs, it emits broken code that fails during runtime parsing.

## 2. The Cognitive Fallacy of Negative Lecturing

In response to user feedback, agents frequently replace hallucinated constructs with explanatory warnings:

> *"Dialect-specific hints such as AS MATERIALIZED or AS NOT MATERIALIZED are rejected by GoogleSQL with syntax errors."*

In thread `1829fe69-d9b7-4916-89ab-8b39dafbd973`, the user firmly rejected this pedagogical lecturing:

> *"Also, i asked to just omit things that are not part of BigQuery, but yet you said 'Dialect-specific hints such as AS MATERIALIZED or AS NOT MATERIALIZED are rejected by GoogleSQL with syntax errors'... just omit... see what else is like that"*

### The Invariant of Complete Omission
Negative warnings produce two adverse operational effects:
1. **Token Priming:** Mentioning foreign syntax tokens in skill documentation primes generative attention heads to emit those exact tokens during code generation.
2. **Context Waste:** Lecturing on unsupported features consumes working context space without providing actionable syntax patterns.

A production tool skill must enforce the **Rule of Complete Omission**: if a clause, flag, or operator does not exist in the target tool, purge every mention of it from all documentation files.

## 3. Systematic Dialect Purity Matrix

The following matrix documents common dialect bleed tokens across analytical engines and specifies their omission protocols:

| Foreign Engine | Foreign Dialect Token | Target Failure Mechanism | Omission Action |
| :--- | :--- | :--- | :--- |
| **PostgreSQL / Snowflake** | `WITH ... AS MATERIALIZED` | Parser rejects keyword `MATERIALIZED` in CTE headers | Purge clause completely; use native temporary tables for intermediate storage |
| **GoogleSQL Legacy** | `SELECT AS VALUE` | Engine rejects clause outside scalar subquery contexts | Purge clause; project standard typed expressions |
| **Oracle / Teradata** | `NVL(x, y)` | Runtime function resolution fails | Omit function; use standard `COALESCE(x, y)` or `IFNULL(x, y)` |
| **MySQL / Presto** | `FROM_UNIXTIME(ts)` | Missing function signature | Omit function; use canonical `TIMESTAMP_SECONDS(ts)` |

## 4. Banning Contrastive Strawmen and AI Buzzwords

Pedagogical text generated by models frequently relies on formulaic contrastive setups ("Unlike tool A which does X, tool B does Y" or "It is not merely a tool, but rather an ecosystem").

Under the project writing specification (`skills/writing/SKILL.md`), contrastive strawmen are prohibited:
- **State Idiomatic Patterns Directly:** Do not compare target features to external platforms unless the user explicitly requests a cross-dialect migration guide.
- **Eliminate Clichés:** Purge decorative verbs and marketing buzzwords.
- **Maintain Formal Systems Tone:** Document what the engine supports, its parameter constraints, and its exact behavioral guarantees.

Enforcing clean omission and direct description produces compact, authoritative skill text that guides agents without triggering syntax hallucinations.
